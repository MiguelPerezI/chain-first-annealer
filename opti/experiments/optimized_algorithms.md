# Optimized versions of the algorithms in *A randomized greedy algorithm for piecewise linear motion planning*

**Source:** C. Ortiz, A. Lara, J. González, A. Borat, arXiv:2008.13290v2 (math.AT, 23 Feb 2021).
**Companion code:** `../src/opti_sc.py` implements every optimized algorithm below (pure Python) and reproduces the paper's two benchmarks.

## 1. What the paper proposes

The paper discretizes Farber's topological complexity `TC` (and, more generally, the homotopic distance
`D(f, g)` of Macías-Virgós and Mosquera-Lois) through *contiguity of simplicial maps*:

* Two simplicial maps `φ, φ' : J → K` are **1-contiguous** if `φ(σ) ∪ φ'(σ)` is a simplex of `K` for every facet `σ` of `J`.
  A **contiguity chain** is a sequence `φ = φ₀, φ₁, …, φ_c = φ'` of consecutive 1-contiguous maps.
* A subcomplex `J ⊆ L` is a **contiguity subcomplex** for `ψ, ψ' : L → K` if `ψ|J` and `ψ'|J` are joined by a contiguity chain.
* The **strict contiguity distance** `SD(ψ, ψ')` is one less than the minimum number of contiguity subcomplexes needed to cover `L`.
  For `L = K × K` (ordered product) and `ψ, ψ'` the two projections, a covering is a *system of piecewise‑linear motion planners* and
  `SD(π₁, π₂) = SC_strict(K) ≥ TC(‖K‖)` (Theorem 3.3 shows equality in the limit of barycentric subdivisions, Definition 3.2).

Section 4 of the paper describes a pipeline of randomized greedy algorithms that produce such coverings:

| # | Algorithm | Role |
|---|-----------|------|
| 0 | `Contiguous(φ, φ')` | primitive: 1‑contiguity test (Definition 2.3.1) |
| 1 | `LocalSearch(φ, φ', M, r)` | random greedy walk that finds a contiguity chain between two maps |
| 2 | `Reduce(φ₀…φ_c)` | shortens a chain by greedy farthest jumps |
| 3 | `AddFacet(J, ψ, ψ')`, `RCC(ψ, ψ')`, `AddFacets(J, ψ, ψ')` | grow a maximal contiguity subcomplex one facet at a time |
| 4 | `Covering(ψ, ψ')` | partition the facets of `L` into contiguity subcomplexes by iterating `RCC` |
| 5 | `OptimizedCovering(ψ, ψ')` | greedy local improvement that reduces the number of parts |

Reported results (Section 5): the circle `∂Δ²` needs 57 s (`M = 1000, r = 0.1`) to certify `SC_strict = 1`;
the wedge of two circles needs 25 min (`M = 5000`) to certify `SC_strict = 2`; a single barycentric subdivision of the circle needs ~10 h.

The rest of this document gives, for each algorithm, the bottleneck of the original, an optimized version, and why the
optimized version still returns a valid answer. The optimizations never weaken the certificates: every chain and every
covering that is output is still verified with Definition 2.3.

## 2. Shared preprocessing (used by every optimized algorithm)

All algorithms in the paper repeatedly ask two questions about the target complex `K`: *is this vertex set a simplex?* and
*how far apart are two vertices in the 1‑skeleton?* The paper delegates both to a generic library (`Contiguous` from SageMath),
recomputing them from scratch at each call. Precomputing the following structures once turns both into O(1)/bitset operations.

```
Preprocess(K):                                    # once per run
  index vertices of K as 0..n-1, facets as 0..m-1
  fmask[F]  ← bitmask over V_K of facet F                       (m words)
  star[v]   ← bitmask over F_K of the facets containing v       (n words)
  dist[u][v]← BFS graph distance in the 1-skeleton of K         (n BFS runs, O(n·|E_K|))
  Ext cache ← empty hash map  S ↦ Ext(S)

IsSimplex(S):        return  AND_{v∈S} star[v] ≠ 0              # O(|S|) word ops, early exit
Ext(S):              # { u ∈ V_K : S ∪ {u} is a simplex }, as a vertex bitmask
                     if S in cache: return cache[S]
                     r ← OR of fmask[F] over the facets F in AND_{v∈S} star[v]
                     cache[S] ← r ; return r

Preprocess(J):       # for every domain complex J ⊆ L that is searched
  starJ[w] ← list of facets of J containing w
```

Costs compared with the paper's black‑box `Contiguous`:

| Operation | Paper (generic) | Optimized |
|---|---|---|
| `S` is a simplex of `K`? | scan facets of `K`: O(|F_K|·dim) | O(|S|) bitset ANDs |
| `Contiguous(φ, φ')` on `J` | O(|F_J|·|F_K|·dim) | O(|F_J|·dim), early exit |
| `d_K(u, v)` | BFS per query | table lookup O(1) |
| all maps `φ[w:=u]` contiguous to `φ` | try each `u`, one `Contiguous` each | one bitmask: `AND_{σ∋w} Ext(φ(σ))` |

Two structural facts about the problem are used throughout, so they are stated once:

* **Locality.** If `f` and `φ` differ only at the vertex `w`, then `f` is simplicial and 1‑contiguous to `φ`
  iff `φ(σ) ∪ {f(w)}` is a simplex for every facet `σ ∋ w` of `J`. Only the star of `w` has to be inspected.
* **Monotonicity (restriction).** If `J' ⊆ J` are generated by facets of `L` and `J` is a contiguity subcomplex, then so is `J'`
  (restrict the chain). Contrapositive: *if `J ∪ σ` is not a contiguity subcomplex, neither is `J'' ∪ σ` for any `J'' ⊇ J`.*
  This is what lets the growth algorithms discard a facet permanently instead of retrying it at every iteration.

## 3. Algorithm 0 — `Contiguous`

**Original.** For every facet `σ` of `J`, test whether `φ(σ) ∪ φ'(σ)` is a simplex of `K` (library call).

**Optimized.**

```
Contiguous(φ, φ', J):                    # full test, early exit
  for σ in F_J:
      if not IsSimplex(φ(σ) ∪ φ'(σ)): return false
  return true

ContiguousDiff(φ, φ', J):                # when φ, φ' are known to be simplicial
  Δ ← { v : φ(v) ≠ φ'(v) }
  if Δ = ∅: return true
  for v in Δ:                            # O(1) necessary condition
      if dist[φ(v)][φ'(v)] > 1: return false        # images of a vertex must be equal or adjacent
  for σ in ∪_{v∈Δ} starJ[v] (each once):            # facets on which the maps agree are simplices already
      if not IsSimplex(φ(σ) ∪ φ'(σ)): return false
  return true
```

* Complexity: O(|Δ| + Σ_{v∈Δ}|starJ[v]|·dim) instead of O(|F_J|·|F_K|·dim).
* Correctness: on a facet where the two maps coincide `φ(σ) ∪ φ'(σ) = φ(σ)` is a simplex because `φ` is simplicial; the adjacency
  pre‑filter is a necessary condition because `{φ(v), φ'(v)} ⊆ φ(σ) ∪ φ'(σ)` must itself be a simplex.

## 4. Algorithm 1 — `LocalSearch`

**Original (Algorithm 1).** Random walk from `φ` toward `φ'` in the space of simplicial maps `J → K`. Each of at most `M`
iterations picks a random vertex `v_j` and a random new value, calls `Contiguous(ϕ, f)`, recomputes `d(f, φ') = Σ_v d_K(f(v), φ'(v))`
and accepts the step if it is contiguous and either improves `d` or a coin with probability `r` says so. Stops when `ϕ = φ'`.
Variant in the text: build the list `L_{ϕ,w}` of all simplicial maps differing from `ϕ` at `w` and pick from it.

**Bottlenecks.**
1. Rejection sampling: a random value `f(v_j)` is almost never admissible when `K` has many vertices, so most iterations are wasted, each paying a full `Contiguous` call.
2. `d(f, φ')` is recomputed over all vertices although only one term changes.
3. Termination requires `ϕ = φ'` exactly, although the walk may become 1‑contiguous to `φ'` much earlier (one more link finishes the chain).
4. Uniform choice of the vertex to mutate: vertices already at their target are mutated as often as the defective ones.
5. Uniform choice among admissible values: no preference for values that approach the target.

**Optimized.**

```
LocalSearch(φ, φ', J, M, r):
  if Contiguous(φ, φ', J): return [φ, φ']
  ϕ ← φ ; Ψ ← [φ]
  defect[v] ← dist[ϕ(v)][φ'(v)]  for v ∈ V_J                     # d(ϕ, φ') = Σ defect
  bad[σ]    ← not IsSimplex(ϕ(σ) ∪ φ'(σ))  for σ ∈ F_J ;  nbad ← #bad
  tabu ← none
  for i ← 1 .. M:
      w ← sample V_J with weight defect[w] + ε                    # bias toward defective vertices
      A ← AND_{σ∈starJ[w]} Ext(ϕ(σ))  minus {ϕ(w)}                # ALL admissible new values, one bitmask
      if tabu = (w, u₀) and |A| > 1: A ← A \ {u₀}                 # do not undo the previous step
      if A = ∅: continue
      if RandomNumber(0,1) < r:  u ← RandomElement(A)             # exploration step
      else:
          u ← argmin_{a∈A} dist[a][φ'(w)]  (random tie-break)     # steepest descent
          if dist[u][φ'(w)] ≥ defect[w]: continue                 # no improving move at w
      tabu ← (w, ϕ(w)) ; ϕ(w) ← u ; defect[w] ← dist[u][φ'(w)]    # O(1) distance update
      for σ in starJ[w]: update bad[σ], nbad                       # O(|starJ[w]|) contiguity-to-target update
      Ψ ← Ψ ∪ [ϕ]
      if nbad = 0:                                                # ϕ is 1-contiguous to φ'  ⇒ done
          if ϕ ≠ φ': Ψ ← Ψ ∪ [φ']
          return Ψ
  return ∅
```

* Every accepted step is 1‑contiguous to the previous one by construction of `A` (the *locality* fact), so `Ψ` is a valid chain;
  the last link is certified by `nbad = 0`, which is exactly `Contiguous(ϕ, φ')` maintained incrementally.
* Cost per iteration: O(|starJ[w]|·dim) bitset work instead of O(|F_J|·|F_K|·dim) plus O(|V_J|) for the distance.
* Every iteration is a *productive* attempt (no rejection sampling), so a much smaller `M` gives the same success probability.
* The parameter `r` keeps its meaning (probability of a non‑greedy step) so the paper's tuning carries over.
* Optional variant: replace the fixed `r` by a simulated‑annealing acceptance `exp(−Δd/T)`; not needed in the benchmarks.

## 5. Algorithm 2 — `Reduce`

**Original (Algorithm 2).** From the current index `j`, scan `i = c, c−1, …` until `Contiguous(φ_j, φ_i)`, jump to `i`.
Worst case O(c²) calls to the full `Contiguous`.

**Observations.**
* Consecutive maps in a `LocalSearch` chain differ at one vertex, so `φ_j` and `φ_i` differ on a *small* set `Δ(j,i)`.
* Contiguity along the chain is not monotone in `i` (so binary/galloping search is not valid and the greedy jump is a heuristic, not an optimum — same as in the paper), but a cheap necessary condition filters almost every candidate in O(1).
* The farthest‑jump greedy is direction dependent; running it backwards is free and often shorter.

**Optimized.**

```
Reduce(Φ = [φ₀ … φ_c], J):
  repeat
      F ← FarthestJump(Φ) ; B ← reverse(FarthestJump(reverse(Φ)))
      Φ' ← shorter of F, B
      if |Φ'| ≥ |Φ|: return Φ
      Φ ← Φ'
  until convergence

FarthestJump(Φ):
  Ψ ← [φ₀] ; j ← 0
  while j < c:
      i ← c
      while i > j+1 and not ContiguousDiff(φ_j, φ_i, J): i ← i−1     # O(1) adjacency pre-filter, then star-restricted check
      Ψ ← Ψ ∪ [φ_i] ; j ← i
  return Ψ
```

* Complexity: the O(1) pre‑filter (`dist ≤ 1` on the differing vertices) rejects most `i`; a full check costs
  O(Σ_{v∈Δ}|starJ[v]|·dim) only when the pre‑filter passes. Total is typically O(c·|Δ|) instead of O(c²·|F_J|·|F_K|).
* Correctness: `Ψ` is a subsequence of `Φ` in which consecutive maps have been verified 1‑contiguous; endpoints are kept.
* The incremental variant (maintain `Δ(j,i)` while decrementing `i`, tracking `#{v : dist[φ_j(v)][φ_i(v)] > 1}`) makes the pre‑filter O(1) amortized per `i`.

## 6. Algorithm 3 — `AddFacet`, `RCC`, `AddFacets`

**Original.** `AddFacet(J)` shuffles the facets of `L` not in `J`, and for each `σ` runs a fresh `LocalSearch(ψ|J∪σ, ψ'|J∪σ)`
until one succeeds. `RCC` iterates `AddFacet` up to `|F_L|` times from a random seed facet; `AddFacets` does the same from a given `J`.

**Bottlenecks.**
1. `RCC` calls `AddFacet` up to `|F_L|` times and each call re‑tries facets that already failed with a smaller `J`.
   By *monotonicity* those facets cannot succeed later (if the failure was genuine), so the paper performs Θ(|F_L|²) `LocalSearch` runs where O(|F_L|) suffice.
2. Every test is a *cold* `LocalSearch` on the whole enlarged complex, although a contiguity chain for `J` is already known, and adding
   a facet usually needs only a tiny modification of it. In `K × K` most facets add **no new vertex**, so the old chain is a chain of vertex maps on `J ∪ σ`
   and only the single facet `σ` has to be verified — O(c) simplex tests, no search at all.
3. The facet order is uniformly random. Facets far from `J` add many new vertices and are the hardest to certify; adjacent facets are the cheapest.
   Random order is still needed for diversity, so a mix is used.

**Optimized.**

```
TryAddFacet(P = (J, Φ, failed), σ, ψ, ψ', M, r):        # returns true and updates P in place on success
  if σ ∈ failed: return false
  new ← vertices of σ not in J
  -- level 1: free certificate ---------------------------------------------------
  if new = ∅ and Φ is a contiguity chain on σ            # ∀i IsSimplex(φ_i(σ) ∪ φ_{i+1}(σ)), O(c)
      J ← J ∪ σ ; return true
  -- level 2: extend the chain on the new vertices by dynamic programming -----------
  if new ≠ ∅:
      states ← V_K^{|new|} (skip this level if too many)
      DP over i = 0..c:  feasible(i, a) ⇔ φ_i[new:=a] simplicial on σ ∧ ∃ b feasible(i−1,b) with
                          IsSimplex(φ_{i−1}[new:=b](σ) ∪ φ_i[new:=a](σ)),  a₀ = ψ(new), a_c = ψ'(new)
      if a path exists: Φ ← extended chain ; J ← J ∪ σ ; return true
  -- level 3: warm-started search (no new vertices) --------------------------------
  if new = ∅:
      k ← longest prefix of Φ valid on σ ; m ← longest suffix of Φ valid on σ
      mid ← LocalSearch(φ_k, φ_m, J ∪ σ, M, r)
      if mid ≠ ∅: Φ ← Reduce(Φ[0..k] ++ mid ++ Φ[m..c]) ; J ← J ∪ σ ; return true
  -- level 4: the paper's cold search ----------------------------------------------
  Φ' ← LocalSearch(ψ|J∪σ, ψ'|J∪σ, J ∪ σ, M, r)
  if Φ' ≠ ∅: Φ ← Reduce(Φ') ; J ← J ∪ σ ; return true
  failed ← failed ∪ {σ}                                  # monotonicity: never retry against this part
  return false

AddFacets(P, C, ψ, ψ', M, r):                            # C = candidate facets; RCC = AddFacets from a random seed facet
  pending ← C \ J
  FreeSweep()                                            # add every σ certified at levels 1–2 (no search)
  while pending ≠ ∅:
      with probability p_explore: σ ← RandomElement(pending)                     # diversity (paper's behaviour)
      otherwise: σ ← argmin_{pending} ( #new vertices , −#shared vertices )      # cheapest first
      pending ← pending \ {σ}
      if TryAddFacet(P, σ, …): FreeSweep()
  return P

RCC(C, ψ, ψ', M, r):
  σ₀ ← RandomFacet(C) ; Φ ← Reduce(LocalSearch(ψ|σ₀, ψ'|σ₀))    # a facet is a contiguity subcomplex when K is connected
  return AddFacets((⟨σ₀⟩, Φ, ∅), C, ψ, ψ', M, r)
```

* **Number of searches.** Each facet is tried at most once per growth run and *most* facets are certified without any search
  (levels 1–2). Growth goes from Θ(|F_L|²) `LocalSearch` runs to O(|F_L|) in the worst case and to O(#hard facets) in practice.
* **Correctness.** Levels 1–3 output a chain each of whose links has been verified on every facet of the new domain
  (old facets by the old chain, `σ` by the explicit tests), so the certificate is exact. Level 4 is the original test.
* **Soft failure cache.** `LocalSearch` is randomized, so a failure is only probabilistic evidence. The implementation
  stores `(chain version, #misses)` and retries a facet once after the part's chain has changed, dropping it after two misses.
  A part that *loses* facets (Section 8) resets its cache, because monotonicity only holds for growth.
* `AddFacets` and `RCC` keep the reduced chain of the current part at all times, which the paper lists as a requirement for the global algorithm.

## 7. Algorithm 4 — `Covering`

**Original (Algorithm 4).** While uncovered facets remain: run `RCC` on the subcomplex they generate, append its facets as a new part.

**Optimized.** `Covering` is a greedy set‑cover procedure whose quality depends on how large each new part is. Two cheap changes:

```
Covering(F_L, ψ, ψ', M, r, k):
  A ← F_L ; 𝒫 ← ∅
  while A ≠ ∅:
      for P in 𝒫, for σ in A:                              # first-fit: offer leftovers to existing parts
          if TryAddFacet(P, σ, …, levels 1–2 only): A ← A \ {σ}
      if A = ∅: break
      best ← ∅
      repeat k times (stop early if best covers all of A):  # greedy set cover: keep the largest of k random maximal parts
          P ← RCC(A, ψ, ψ', M, r) ; if |P| > |best|: best ← P
      𝒫 ← 𝒫 ∪ {best} ; A ← A \ best
  return 𝒫
```

* The subtraction `(Facets(J) ∩ F_L) \ ∪Q` in the paper's line 6 is redundant: `RCC` runs on the complex generated by `A`, so its facets are already uncovered. Removed.
* The `k` restarts are independent and trivially parallel.
* Each part is stored together with its (reduced) contiguity chain, so the output of `Covering` is already an explicit system of motion planners.

## 8. Algorithm 5 — `OptimizedCovering`

**Original (Algorithm 5).** Starting from `Covering`, iterate `N` times (or until `|𝒫| ≤ t`): sort parts by decreasing size; with a cyclic index `j`,
build a random contiguity subcomplex `J_P` from `P_j ∪ … ∪ P_p` (keep the larger of it and `P_j`); grow it with `AddFacets` inside
`P_{j−1} ∪ … ∪ P_p` (keep the larger of it and `P_{j−1}`); replace `P_{j−1}, P_j, …` by `Q, P_{j−1}−Q, P_j−Q, …`, delete empties;
revert if the number of parts increased.

**Observations.**
1. The acceptance test looks only at `|𝒫|`. Between two decrements the loop cannot tell progress from drift, and it accepts moves that
   make the partition *more balanced*, which moves away from eliminating a part. A secondary potential fixes this at zero cost.
2. The move that actually eliminates a part (visible in the paper's Figure 2) is "the smallest part gets absorbed by the large ones".
   It can be attempted directly and cheaply with the level 1–2 certificates before spending any search.
3. Facets that a part has already failed to absorb need not be retried while that part only grows (monotonicity).
4. Every part keeps its chain, so `AddFacets` in step (3) is warm (Section 6) instead of cold; `RCC` in step (2) still starts from a random facet, which is the intended source of diversity.
5. A fixed `N` is replaced by a stagnation counter plus an optional wall‑clock budget.

**Optimized.**

```
Potential(𝒫) := ( |𝒫| , −Σ_P |P|² )                       # lexicographic: fewer parts, then more lopsided sizes

OptimizedCovering(ψ, ψ', M, r, N, t, patience):
  𝒫 ← Covering(ψ, ψ', M, r, k) ; j ← 0 ; stale ← 0
  while iterations < N and |𝒫| > t and stale < patience:
      before ← Potential(𝒫)
      -- Move A: absorb the smallest part ---------------------------------------------
      sort 𝒫 by decreasing size ; S ← last part ; W ← copies of the others
      for level in (free certificates only, then with search):
          for σ in S, for P in W (largest first): if TryAddFacet(P, σ, …, level): mark σ absorbed; break
          if all of S absorbed: 𝒫 ← W ; stale ← 0 ; continue outer loop
      -- Move B: the paper's step (2)+(3), warm and with the improved acceptance test ------
      D ← P_j ∪ … ∪ P_p
      J_P ← RCC(D, ψ, ψ', M, r) ; if |J_P| < |P_j|: J_P ← P_j (with its chain)
      D' ← D ∪ P_{j−1} (if j > 0)
      J_Q ← AddFacets(J_P, D' \ J_P, ψ, ψ', M, r) ; if j > 0 and |J_Q| < |P_{j−1}|: J_Q ← P_{j−1}
      𝒫' ← DeleteVoids({P₀, …, P_{j−2}, J_Q, P_{j−1} − J_Q, P_j − J_Q, …, P_p − J_Q})
             (a part that shrank gets its chain restricted to its remaining vertices, re-Reduced, and its failure cache cleared)
      if Potential(𝒫') ≤ before: 𝒫 ← 𝒫'                     # never accept a worse partition; accept sideways moves that unbalance
      stale ← 0 if Potential(𝒫) < before else stale + 1
      j ← (j + 1) mod |𝒫|
  Reduce every chain ; return 𝒫
```

* Termination and output validity are unchanged: every part is a contiguity subcomplex with an explicit, verified chain, and the parts partition `F_L`.
* Move A costs O(|S|·|𝒫|·c) simplex tests when it succeeds through free certificates, which is the common case near the end of the run.
* The potential turns the plateau between two part‑count decrements into a monotone descent, which is what a greedy algorithm needs to make steady progress.

## 9. Summary of the optimizations

| Algorithm | Main change | Effect |
|---|---|---|
| `Contiguous` | bitset facet index, `Ext` cache, adjacency pre‑filter, star‑restricted checks | per‑test cost O(|F_K|·dim·|F_J|) → O(dim·#touched facets) |
| `LocalSearch` | exact enumeration of admissible moves, O(1) distance update, incremental "contiguous‑to‑target" stop, defect‑weighted vertex choice, steepest step, tabu | no wasted iterations; far fewer iterations needed; shorter chains |
| `Reduce` | O(1) pre‑filter, diff‑restricted checks, forward+backward passes to fixpoint | O(c²·|F_J|·|F_K|) → ≈O(c·|Δ|) |
| `AddFacet`/`RCC`/`AddFacets` | persistent candidate set with monotone failure cache, chain reuse (free / DP / warm), adjacency‑first with random exploration, free sweeps | Θ(|F_L|²) searches → O(#hard facets) searches |
| `Covering` | first‑fit to existing parts, `k` restarts keep largest part (greedy set cover), redundant set difference removed | fewer, larger parts to start from |
| `OptimizedCovering` | absorb‑smallest move, lexicographic potential, warm `AddFacets`, failure caches, stagnation stop | monotone progress; part elimination found directly |

What is **not** changed and cannot be: the problem of finding a minimum covering by contiguity subcomplexes is a set‑cover‑like
combinatorial problem, and deciding whether two maps are in the same contiguity class is itself a hard search. The algorithms remain
randomized heuristics with the same guarantee as in the paper (every output is a valid, explicitly certified system of piecewise‑linear
motion planners, hence an upper bound `SC_strict(K) ≤ |𝒫| − 1`); the optimizations change how fast such a certificate is found, not what it proves.

## 10. What the GPU port of the paper (`Abstract_Motion_GPU`) does, and what it cannot fix

The sibling repository ports the paper's Algorithms 1–5 *verbatim* to CUDA: one block per `AddFacet` test, one thread per
random walk (`ghost_kernel`), incremental contiguity and distance updates, `splitmix64` streams so a winning walk is replayed on
the CPU to materialize its chain. It certified `SC_strict(∂Δ³) = 2` (S², 3 domains, 265 s) and `SC_strict(∂Δ⁴) ≤ 19` (S³, 20 domains, 2 h 45 m).

Its measured bottleneck is exactly the one Part I identified: **every test is a cold search from `π₁` on the whole enlarged domain**
(Section 6, bottleneck 2). At `|J| ≈ 100` on S³ a round of ~400 tests costs ~160 s and the acceptance rate falls to a few percent
(`results/s3_scaffold_v2`: 84 → 106 facets in one hour). More GPU throughput lowers the constant, not the exponent.

## 11. Kernel B — the optimized `LocalSearch` on the GPU (`ls_kernel`)

Section 4's algorithm, batched like the paper's walk (one block per test, `W` threads = `W` independent walks) with two additions:

* **arbitrary start and target maps** per test (warm starts of Section 6, level 3, become one kernel argument);
* **cooperative early exit**: the first successful walk of a block raises a shared flag polled every 64 iterations.

Per iteration a thread does: defect‑weighted vertex choice (weights `4·defect+1`, O(|V_J|)); the admissible set
`A = ∩_{σ∋w, σ∈J} Ext(φ(σ)) \ {φ(w)}` as a bitmask over `V_K` (one `is_simplex` lookup per facet and value); tabu; steepest step or
exploration step; O(|star(w)|) update of the "bad facet" bitset that realizes the *contiguous‑to‑target* stop. The walk body is
written once and compiled twice (`cuda.jit(device=True)` and `njit`), so the **CPU twin is the same source** and replay is exact.

## 12. Kernel A — the chain‑first formulation (`chain_anneal_kernel`)

Level 1 of Section 6 (a chain is a *free* certificate for every facet on which its links stay simplices) has a converse that
removes the `AddFacet` search entirely:

> For any chain of vertex maps `Φ = (π₁ = φ₀, φ₁, …, φ_c = π₂)` defined on **all** of `V_L`, the set
> `D(Φ) = { σ ∈ F_L : φ_i(σ) ∪ φ_{i+1}(σ) ∈ K for all i }`
> is a contiguity subcomplex with certificate `Φ|_{V(D(Φ))}`; conversely every contiguity subcomplex `J` is contained in `D(Φ)`
> for some such `Φ` (extend its chain arbitrarily outside `V_J`).

Hence `SC_strict(K) + 1 = min { k : ∃ Φ¹…Φᵏ with D(Φ¹) ∪ … ∪ D(Φᵏ) = F_L }`, and the covering problem becomes an
**unconstrained combinatorial optimization over k‑tuples of chains**, with objective the number of facets covered by at least
one chain. Evaluating a change of one entry `φ_i(w)` touches only the two links `(i−1, i)`, `(i, i+1)` on the facets of
`star(w)`; a facet's status is `bad_j[σ] = #{ i : link i invalid on σ }`, kept per chain.

**Algorithm (one GPU thread = one independent annealer on a k‑tuple of chains):**

```
state:  ch[j][i][v] ∈ V_K  (j < k, 0 ≤ i ≤ c, v ∈ V_L), ch[j][0] = π₁, ch[j][c] = π₂ fixed
        bad[j][σ] link-violation counts;  E = Σ_σ w_σ·pen(min_j bad[j][σ]),  pen(0)=0, pen(b)=1+β·b
        cov = #{σ : min_j bad[j][σ] = 0}          (unweighted; drives best-state tracking)
move:   chain j, vertex w, block of consecutive interior maps i₁..i₂ (length 1 w.p. 1−p_track, else 2..8),
        new value u (uniform, or copied from φ_{i₁−1}(w) / φ_{i₂+1}(w) w.p. p_copy — creates/removes duplicate maps)
        ΔE from the links i₁−1..i₂ on star(w) only;  Metropolis acceptance at temperature T (geometric T₀ → T₁ per epoch)
epoch:  S threads × `iters` moves; host then clones the elite over the weakest 25 % (every 2nd epoch), re‑seeds a few slots,
        and (optionally) raises the weight w_σ of the facets the best state leaves uncovered (guided local search)
output: best k-tuple; parts P_j = D(Φʲ) \ ∪_{l<j} D(Φˡ); chains restricted and shortened with Reduce; verified with Definition 2.3
```

Duplicate consecutive maps are trivially contiguous, so a fixed `c_max` costs nothing: the chain uses as many links as it needs.
Initial chains switch the grid vertices from `π₁` to `π₂` one at a time in random order.

Why this suits the GPU: the state is a few KB of `int8` per thread, every move is a fixed‑size loop over `star(w)`
(≤ 320 facets on S³), there is no host round‑trip per test, and independent annealers are embarrassingly parallel
(measured 3–5 M moves/s on the T4 for S³ with `k = 2`, `S = 4096`).

### 12.2 The two‑chain plateau on S³

Every `k = 2` run reaches exactly 460 covered facets, and the top of the population (best states) converges to 460. The 40 uncovered facets differ

facets of one product `σ × τ` of two tetrahedra). Whether 460 is a theorem (`SC_strict(∂Δ⁴) = 2` at subdivision level 0,

### 12.3 Where the chain‑first search fails: the circle

On `∂Δ²`, `is_simplex(S) ⇔ |S| ≤ 2`, so an interior map may use only two of the three values on every facet and chains must
"wind" (the CPU certificate's chains have 6 links and pass through maps far from both projections). Single‑entry and track
moves cannot cross the intermediate low‑coverage states; the population stalls at 13–14 of 18 even at high temperature and
with guidance, although the kernel scores the known certificate at 18/18. **Update (Part III, §14): this was a defect of the energy, not of the formulation — with the corrected energy the annealer solves the circle in under 15 s.** The two approaches were believed to be complementary:
Part I's growth pipeline (search per facet, chain reuse) handles small, tightly constrained `K`; the chain‑first annealer
handles large `K × K` where facets have many admissible images. A hybrid (seed the annealer with chains produced by
`ls_kernel` on grown domains) is the natural next step and is supported by the `--init` option.

*A necessary condition that is checked but does not explain 460.* If `J` is a contiguity subcomplex then `π₁|J ≃ π₂|J`; on a

chains of a pair exclude *different* slices, so the condition explains 0 of the 40 uncovered facets. The invariant "40" must
come from a finer obstruction (the excluded facets of the two chains cannot be made disjoint), which we leave as a conjecture:

> **Conjecture.** Two contiguity subcomplexes of the staircase triangulation of `∂Δ⁴ × ∂Δ⁴` cover at most 460 of its 500 facets;
> hence `SC_strict(∂Δ⁴) = 2` at subdivision level 0, and the 3‑domain certificate of §12.1 is optimal at this level.
> (`TC(S³) = 1` would then be reached only after subdivision, unlike `S¹` and `S²` where level 0 is already sharp.)

Practical note: track moves cost ~7× per move in this kernel (dynamic local‑array indexing) and did not change the outcome, so
`--ptrack` now defaults to 0.05; point mutations run at 4 M moves/s on the T4.

# Part III — The Császár torus, and the energy fix that came out of it (2026‑09‑18)

## 13. The target: `T²` as the Császár torus

`K` = the 7‑vertex, 14‑triangle triangulation of the torus (`Aᵢ = {i, i+1, i+3}`, `Bᵢ = {i, i+2, i+3}` mod 7; the unique
facet‑minimal torus, 1‑skeleton `K₇`). `K × K` has `14² · C(4,2) = 1176` maximal facets (5 vertices each) on the `7 × 7` grid,
so a grid vertex lies in 120 facets. `is_simplex(S)` holds for `|S| ≤ 2` always, for `|S| = 3` only for the 14 triangles
(of 35 triples), never for `|S| ≥ 4`. Compared with `∂Δ⁴` (every proper subset of the 5 vertices is a simplex) the landscape is
far more constrained: most single‑entry changes break every facet in the star of the entry.

**Theoretical floor — corrected.** The GPU repo's notes derived "expected minimum 2 domains" from "TC(G) = 1 for every
path‑connected topological group". Farber's theorem for topological groups is `TC(G) = cat(G)`, and `cat(T²) = 2` (reduced;
cup‑length 2), so **`TC(T²) = 2` and any cover needs at least 3 domains**; a 3‑domain cover would give `SC_strict(T²) = 2 = TC(T²)`
at subdivision level 0. The GPU repo docs were corrected (`docs/EXECUTION.md` §12.2, `README.md`, `note.txt`); the
`--target-domains 2` hint given to its Algorithm 5 was one below the floor and had no effect on the outcome.

**State of the art before this session** (`Abstract_Motion_GPU/results/torus_v2`, paper pipeline on the GPU, 11.3 h): a
35‑domain cover of which only 26 chains could be verified within budget (`M = 60 000`, 1024 walks) — no bound at all. Largest
domains 164, 122, 114 facets; the verified chains have 15–47 maps after reduction.

## 14. Diagnosis on the circle, and the fix

The circle (`∂Δ²`, 18 facets, 9 grid vertices) is the smallest instance of the failure and runs in seconds, so it was used as
the test bed. All probes: `k = 2`, `S = 1024`, `iters = 20 000`, seed 5, 30 s limit.

### 14.1 What the stuck states look like

The best two‑chain state of a stuck run (`cmax = 40`, 15/18) has chains of **35 and 41 distinct maps** (out of 41) whose
domains are only 9 and 6 facets, and which reduce (Algorithm 2) to **3 and 5 links** on those domains. The other 30+ maps are
noise: under the energy `Σ_f w_f · pen(min_j bad_j[f])` an entry of chain `j` that only touches facets already covered by the
other chain has *no* energy at all, so it random‑walks at any temperature. Once chain 1 covers `f`, chain 0's forty links on
`f` decay, and chain 0 can never take `f` back (it would have to repair all forty links at once). Facet hand‑offs between
chains — exactly what is needed to leave a `(14, 4)` split for the `(10, 8)` certificate — become impossible. This is the
partition trap, and it also explains why longer chains were *worse* (more links to decay).

The torus baseline state (`torus_k4_L1`, 618/1176) shows the same picture at scale: all four chains have **41 distinct maps
out of 41**, their domains (160, 175, 140, 160) reduce to **9, 7, 9, 5 links**, and on a typical facet outside a chain's
domain that chain has **24–26 bad links** (median), so covering a new facet with an existing chain means repairing about 25
links — unreachable by single‑entry moves. The four domains are almost disjoint (pairwise overlaps 0–11), i.e. no slack for
hand‑offs.

Second defect: `pen(b) = 1 + β·b` with `β = 0.05` is flat — a facet with 1 bad link costs 1.05 and with 30 bad links 2.5 —
so there is almost no gradient toward repairing a facet link by link.

### 14.2 The fix: steeper slope, per‑chain cleanliness, track moves

New energy (kernel A, `--beta`, `--gamma`):

```
E = Σ_f w_f · pen(min_j bad_j[f])  +  γ · Σ_j Σ_f bad_j[f],      pen(0) = 0,  pen(b) = 1 + β·b
```

The `γ` term charges every chain for every bad link, whether or not another chain covers the facet, so each chain stays
contiguous wherever it can and keeps a *latent* domain much larger than its unique contribution; hand‑offs then cost `O(1)`
instead of `O(cmax)`. It is one extra multiply‑add in the delta (the per‑facet `d = nb − ob` is already computed).
Track moves (`--ptrack`, a block of consecutive maps set to one value) attack the same problem from the move side by
re‑creating duplicate blocks.

## 16. What the annealer found: product domains, and an explicit certificate without search

### 16.1 The 216‑facet ceiling is `star(v) × star(v)`

Every 216‑facet domain produced with the corrected energy (`k = 3, 4`, chain lengths 20 and 40, different seeds) is **exactly
the product `A × A` of a 6‑triangle sub‑complex `A ⊂ K` with itself**: 36 pairs of triangles `(s, t)` with `s, t ∈ A`, all six
staircase facets of each pair. Each `A` is a **closed vertex star** `star(v)` (7 vertices, 12 edges, 6 triangles, `χ = 1`,
boundary a single 6‑cycle — the link of every vertex of the Császár torus is a 6‑cycle because the 1‑skeleton is `K₇`), and
an exhaustive check over all triangle subsets shows that the 7 vertex stars are the *only* disk sub‑complexes with 6
triangles and that **no disk sub‑complex has 7 or more** (5 triangles: 84 disks, 6: 7, ≥ 7: none). The 210‑ and 193‑facet
domains are the same rectangles with a few pairs missing. The baseline (old energy) domains were *not* products
(52–71 pairs touched, only 3–10 complete) and were smaller (140–175).

Why the search lands there: on `D(v, w) = star(v) × star(w)` the chain

```
π₁  ∼  c_v  ∼  c_w  ∼  π₂           (c_x = the constant map to x)
```

is 1‑contiguous — on a facet `σ` over the pair `(s, t)`: `π₁(σ) ∪ c_v(σ) = s`, `c_v(σ) ∪ c_w(σ) = {v, w}` (an edge; for
non‑adjacent `v, w` insert the constants along a shortest path), `c_w(σ) ∪ π₂(σ) = t`. With `v = w` the chain has **2
links**, which is what the annealer's chains reduce to (§14.1, 2–3 links). The `γ` term rewards short clean chains, so the
population converges on these maximal product domains. Generally: for any complex, `D(v, w)` is a contiguity domain, so

> **`SC_strict(K) ≤ ρ(K) − 1`, where `ρ(K)` is the minimum number of rectangles `star(v) × star(w)` covering all pairs of
> facets of `K`.**

For `∂Δ⁴`: `star(v)` has 4 of the 5 facets, a row needs 2 stars to be covered, so `ρ ≥ 3·5/4 → 3`, and 3 rectangles do it —
the 3‑domain S³ certificate of Part II re‑derived by hand (`results/s3_starcover`: 320 + 140 + 40, chains of 2 links, audited).
For the torus a row `s` needs vertices `w` whose stars cover all 14 triangles (a vertex cover of the triangle hypergraph; its
minimum size is 4), so `Σ_j |star(v_j)| = 6ρ ≥ 4·14` and **`ρ ≥ 10`**; a product cover therefore cannot certify better than
`SC_strict ≤ 9`, and **no product cover can reach the floor of 3 domains** — that needs genuinely non‑product domains
(the continuous 3‑set cover of `T² × T²` uses `{(a, b) : a⁻¹b ∈ Vᵢ}`, not products).

### 16.3 A negative result: the translation ansatz

The continuous 3‑set cover of `T² × T²` is translation invariant, `{(a, b) : b − a ∈ Vᵢ}`, and the Császár torus's vertex set
is `Z₇` acting by simplicial automorphisms, so the natural next idea was to restrict the search to chains
`φᵢ(a, b) = a + ψᵢ(b − a)` (7 values per map instead of 49; `gpu_sc_equiv.py`). This is *not* a symmetry of the staircase
product — the diagonal shift wraps a monotone path around — so the facets cannot be reduced to orbits, and worse, the ansatz
is too restrictive: on `S²` the whole population of 2048 states caps at **exactly 60/96** with three chains, on the circle at
14/18 (the paper's circle chains are not of this form). Kept for the record (self‑check included: the parametrised bad counts
equal the full‑product bad counts on every facet); not used further.

### 16.4 Single‑chain ceiling without the cleanliness term

`torus_k1_c40_g0` (one chain, `beta 5`, `gamma 0`, `ptrack 0.3`, 40 links, 10.8 min): **228 facets** (206, 222, 226, 228 per
epoch — a plateau), above the 216‑facet product ceiling. The domain is a *generalized product*: the reduced chain has 3 links
`π₁ ∼ f ∼ g ∼ π₂` where `f` and `g` take values in the single triangle `B₄ = {0, 4, 6}` (so `f ∼ g` is automatic), `f(σ) ⊆ s`
and `g(σ) ⊆ t` on a facet over `(s, t)`; it touches 48 triangle pairs (16 complete, 16 with 5 of 6 facets, 4 with 4, 12 with 3)
on 7 rows × 7 columns. So `gamma = 0.5` was trading some domain size for cleanliness, but the best single domains found by
any method remain short‑chain (≤ 3 links) constructions of at most 228 facets — far from the ≈ 392 that three domains would
need. Long random chains (the paper's pipeline, 15–47 maps) gave *smaller* domains (≤ 169).


### 16.5 Diagonal bands, and an exact obstruction test (`band_test.py`, `h1_obstruction.py`)

The continuous 3‑set cover of `T² × T²` is made of "bands around the diagonal", so the natural non‑product candidates are
`D_diag` (facets over pairs `(s, s)`), `D_edge` (`|s ∩ t| ≥ 2`) and `D_vert` (`s ∩ t ≠ ∅`). `D_diag` (84 facets) is a domain
with a **0‑link** chain (`π₁(σ) ∪ π₂(σ) = s`). `D_edge` (336) and `D_vert` (1092) admit no chain in 4 × 128 walks × 20 000
steps — and the reason is not the budget:

> **H₁ test.** A contiguity domain `J` has `π₁|J ≃ π₂|J`, so `(π₁ − π₂)∗ = 0 : H₁(|J|) → H₁(|K|)`. `h1_obstruction.py`
> computes this over `GF(2)` (boundary matrices of the sub‑complex spanned by `J`, cycle basis, push‑forward of each cycle
> along both projections, rank modulo the boundaries of `K`).

| `J` | facets | `dim H₁(J; Z₂)` | `rank (π₁ − π₂)∗` | verdict |
|---|---:|---:|---:|---|
| `D_diag` | 84 | 2 | 0 | passes (and is a domain) |
| `D_edge` | 336 | 5 | 2 | **obstructed** |
| `D_vert` | 1092 | 4 | 2 | **obstructed** |
| all of `K × K` | 1176 | 4 | 2 | obstructed (as it must be: `TC > 0`) |
| the 228‑facet domain of §16.4 | 228 | 0 | 0 | passes |

The test is exact and cheap (milliseconds), so it can prune candidate domains before any walk is spent, and it explains the
S³ "slice" condition of §12.4 as the `H₃` version of the same statement. It also frames the open question precisely: a
3‑domain level‑0 cover of the torus needs three ≈ 392‑facet facet sets on each of which `(π₁ − π₂)∗` vanishes on `H₁`
*and* which admit chains; every large candidate tried so far fails the first condition or is a (generalized) product of
≤ 228 facets.

*Difference bands.* Since the vertex set of the Császár torus is `Z₇`, the sets `D_W = {facets all of whose vertices `(a, b)`
have `b − a ∈ W}` (`W ∋ 0`) are the discrete analogues of the translation‑invariant sets `{b − a ∈ V}`. All 22 such sets
with ≥ 150 facets (sizes 154–584) have `H₁` obstruction rank 2 — none is a domain. The staircase product is not
translation invariant, and the bands inherit loops on which the two projections differ.

## 19. Theorems and corollaries extracted from the experiments

Notation as in the paper: `K` a finite connected simplicial complex on the ordered vertex set `V`, `K × K` its ordered
(staircase) product, `π₁, π₂` the projections, `SC_strict(K) = SD(π₁, π₂)`. For a vertex `v`, `star(v)` is the set of facets of
`K` containing `v`, and `c_v : V × V → V` the constant map. For a set `A` of facets of `K`, the sub‑complex it spans is also
written `A`. All statements are at subdivision level 0.

**Theorem 1 (product domains).** For vertices `v, w` of `K` let `D(v, w) ⊆ K × K` be the set of maximal facets lying over
pairs `(s, t)` of facets of `K` with `v ∈ s` and `w ∈ t` (so `|D(v, w)| = |star(v)| · |star(w)| · #paths`). Then `D(v, w)` is a
contiguity domain for `(π₁, π₂)`: if `v = v₀, v₁, …, v_m = w` is a path in the 1‑skeleton of `K`,

```
π₁  ∼  c_{v₀}  ∼  c_{v₁}  ∼  …  ∼  c_{v_m}  ∼  π₂       on D(v, w),
```

a chain of `m + 2` links (`2` links when `v = w`).

*Proof.* Let `σ ∈ D(v, w)` lie over `(s, t)`; its vertices are `(a, b)` with `a ∈ s`, `b ∈ t`, so `π₁(σ) = s` and `π₂(σ) = t`
(every vertex of `s` and of `t` occurs, because a staircase path visits every row and every column). Every map in the chain is
simplicial on `σ`: `π₁(σ) = s`, `π₂(σ) = t`, `c_x(σ) = {x}`. Consecutive maps are 1‑contiguous on `σ`: `π₁(σ) ∪ c_v(σ) = s ∪ {v} = s`
(as `v ∈ s`); `c_{vᵢ}(σ) ∪ c_{vᵢ₊₁}(σ) = {vᵢ, vᵢ₊₁}` is an edge of `K`; `c_w(σ) ∪ π₂(σ) = t`. ∎

Verified mechanically for every rectangle used below (`star_cover.py` runs `verify_system`, and `independent_check.py` re‑checks
each chain with no shared code).

**Corollary 2 (a search‑free upper bound).** Let `ρ(K)` be the minimum number of rectangles `D(v, w)` covering all pairs of
facets `(s, t)` of `K`, i.e. the minimum size of a set `R ⊆ V × V` such that for every `(s, t)` there is `(v, w) ∈ R` with
`v ∈ s`, `w ∈ t`. Then

> **`SC_strict(K) ≤ ρ(K) − 1`.**

`ρ(K)` is a set‑cover problem with `|V|²` sets over `|F|²` elements, solved exactly by an integer program in seconds for every
complex considered here (`circle 3, ∂Δ³ 3, ∂Δ⁴ 3, ∂Δ⁵ 3, wedge of two circles 4, Császár torus 11`). *Proof.* Assign each facet
of `K × K` to the first rectangle of `R` containing its pair; Theorem 1 gives the chains; a partition of the facets into
`ρ(K)` domains is a system of `ρ(K)` motion planners. ∎

**Corollary 3 (all boundary‑of‑simplex spheres).** For every `n ≥ 1`, `ρ(∂Δⁿ⁺¹) = 3`, hence

> **`SC_strict(∂Δⁿ⁺¹) ≤ 2` for all `n ≥ 1`, and `SC_strict(∂Δⁿ⁺¹) = 2 = TC(Sⁿ)` for all even `n ≥ 2`** — sharp at subdivision
> level 0 for every even‑dimensional sphere.

*Proof.* The facets of `∂Δⁿ⁺¹` are `s_a = V ∖ {a}`, `a ∈ V = {0, …, n+1}`. Take `R = {(0,0), (1,1), (2,2)}`. A pair `(s_a, s_b)` is
missed by `(v, v)` iff `v ∈ {a, b}`; it is missed by all three iff `{0, 1, 2} ⊆ {a, b}`, impossible. So three rectangles cover.
Two rectangles `(v, w), (v', w')` never suffice: the pair `(s_v, s_{w'})` is missed by both. Hence `ρ = 3` and `SC_strict ≤ 2`.
For even `n`, `TC(Sⁿ) = 2` (Farber) and `TC(‖K‖) ≤ SC_strict(K)` (González) give equality. ∎

Explicit, audited certificates: `∂Δ²` (S¹: 8 + 6 + 4, `results/circle_starcover`), `∂Δ³` (S²: 54 + 30 + 12, `results/s2_starcover`), `∂Δ⁴` (S³: 320 + 140 + 40),
`∂Δ⁵` (S⁴: 1750 + 630 + 140, `S4_certificate.md`), all with two‑link chains; the S² and S³ values coincide with the paper's
computational results (3 domains) and with the GPU searches of Part II and §17, which produce exactly these rectangles.

**Remark (odd spheres).** For odd `n`, `TC(Sⁿ) = 1`, so Corollary 3 leaves `SC_strict(∂Δⁿ⁺¹) ∈ {1, 2}`. For `n = 1` the paper's
two non‑product domains show `SC_strict(∂Δ²) = 1 < ρ − 1`; for `n = 3` every two‑chain state found by any of our searches is a
two‑rectangle cover (460 = 23 · 20 facets, §17), and we conjecture `SC_strict(∂Δ⁴) = 2` at level 0.

**Corollary 4 (Császár torus).** `ρ(T²_Császár) = 11` (integer program), so **`SC_strict(T²_Császár) ≤ 10`**; with
`TC(T²) = 2` the value lies in `{2, …, 10}`. This is the first verified simplicial‑complexity bound for a torus in this framework
(the previous run left 9 of 35 chains unverified). *Lower bound on `ρ` by counting:* for a fixed row `s`, the rectangles `(v, w)` with `v ∈ s` must have `w`'s covering all
14 triangles, i.e. a vertex cover of the triangle hypergraph, whose minimum size is 4 (exhaustive check). Summing over the 14
rows, `Σ_{(v,w) ∈ R} |star(v)| = 6ρ ≥ 4 · 14`, so `ρ ≥ 10`; the integer program shows 10 is not enough and 11 is.

**Theorem 5 (generalised products).** Let `A, B` be sets of facets of `K` such that the identity of the sub‑complex `A` is joined
to a constant map `c_v` by a chain of 1‑contiguous simplicial maps `A → K` (`A` is *contiguity‑contractible in `K`*), and
likewise `B` to `c_w`. Then `A × B` (all facets of `K × K` over pairs `(s, t) ∈ A × B`) is a contiguity domain. *Proof.* On
`A × B`, `π₁` is the composite of the projection to `A` with the inclusion, so the chain `id_A ∼ … ∼ c_v` composed with the
projection is a chain `π₁ ∼ … ∼ c_v` (contiguity is preserved by pre‑composition); join `c_v ∼ … ∼ c_w` along a path and
`c_w ∼ … ∼ π₂` symmetrically. ∎ Vertex stars are the case of one link (`σ ∪ {v}` is a simplex for `σ ∈ star(v)`). Consequently,
if `K` is covered by `m + 1` contiguity‑contractible sub‑complexes (the *simplicial LS category* in the contiguity sense is
`≤ m`), then `SC_strict(K) ≤ (m + 1)² − 1`. For the Császár torus the vertex‑star cover needs 4 stars (minimum vertex cover of
the triangles is 4), giving only 15; the rectangle optimum 11 is better because it uses `star(v) × star(w)` with `v ≠ w`.

**What we conjecture and could not prove.**
* *(C1)* `SC_strict(∂Δ⁴) = 2` at level 0 (the S³ two‑domain question). Evidence: ten old‑energy and two corrected‑energy
  two‑chain searches all converge to two‑rectangle covers; the largest non‑product domain seen has 329 of 500 facets.
* *(C2)* For the Császár torus, no level‑0 system with 3 domains exists (i.e. `SC_strict` is not sharp at level 0 for `T²`).
  Evidence: every large candidate domain fails the `H₁` obstruction (§16.5), the largest domain found by any method has
  228 facets (a 3‑domain cover needs ≈ 392), and all hybrid searches plateau.
* *(C3)* The search‑free bound of Corollary 2 is attained by the paper's greedy pipeline and by our annealer whenever they
  succeed on `∂Δⁿ⁺¹`: the domains they find are (sub‑)rectangles. The S⁴ two‑chain run was *predicted* to stop at `34 · 70 = 2380` before it ran, and did
  (§20) — the third sphere (after S³'s 460 and S²) where the two‑chain plateau is exactly the two‑rectangle number. A proof would need to show that maximal contiguity domains
  of `(π₁, π₂)` with short chains are products.

## 20. S⁴ = ∂Δ⁵

`K = ∂Δ⁵`: 6 vertices, 6 facets (4‑simplices), `K × K` has `36 · C(8,4) = 2520` maximal facets with 9 vertices each on the
`6 × 6` grid. `TC(S⁴) = 2`, so the floor is 3 domains.

* **Explicit certificate (Corollary 3):** `D(0), D(1), D(2)` → disjoint parts 1750 + 630 + 140, two‑link chains, verified and
  audited (`results/s4_starcover`, `S4_certificate.md`; the auditor `independent_check.py` was extended to `n = 5`). Hence

## 21. S⁵ … S⁸ with the star cover, and where the facet-by-facet certificate stops

Corollary 3 is constructive at every `n`: for `K = ∂Δ^{n+1}` the three rectangles `D(v) = star(v) × star(v)`,
`v = 0, 1, 2`, cover every pair of facets. Two `(n+1)`-subsets of an `(n+2)`-set share at least `n ≥ 2` vertices, so
each pair `(s, t)` has a common vertex among `{0, 1, 2}` — otherwise `s ∩ t` would lie in `{3, …, n+1}`, which has
only `n − 1` elements. Assigning every facet to the smallest such `v` partitions `K × K` into domains of closed-form
size

| domain | facets |
|---|---:|
| `D(0)` | `(n+1)² · C(2n, n)` |
| `D(1) \ D(0)` | `(2n+1) · C(2n, n)` |
| `D(2) \ D(0) ∪ D(1)` | `2 · C(2n, n)` |

summing to `(n+2)² · C(2n, n)` — the total number of staircase facets of `∂Δ^{n+1} × ∂Δ^{n+1}`. The chains are
`π₁ ∼ c_v ∼ π₂` at every `n`, and `reduce_chain` removes nothing from them (verified byte-identical with and without
`--no-reduce` at `n = 5`), so the certificate is computed in closed form, never searched.

**The wall.** Three independent limits stop the facet-by-facet certificate at S⁸:

* `gpu_sc.Product` indexes vertices by int8 grid ids, so `ngrid = (n+2)² ≤ 127` — `n ≤ 9` (S⁹ itself is the last that

* the auditor represents each facet as plain Python tuples, ≈ 2.8 KB per facet: 3.59 GB at S⁸, hence ≈ 16.5 GB at S⁹

`stream_starcover.py` addresses the regime above the wall: it verifies the *same* construction without materializing

data rather than assumed. Cross-checked against the audited full certificates, it reproduces the S⁵–S⁸ domain sizes

## 24. The barycenter triangle: `SC_strict = 0`, and the middle map is (almost) forced

Take Δ² with vertices `{0,1,2}` and split it by its **barycenter** `3` into the three triangles
`{0,1,3}`, `{0,2,3}`, `{1,2,3}`. As a complex `K` has 4 vertices, all 6 edges of `K₄` (the three inner edges
`{0,3},{1,3},{2,3}` are each shared by two of the triangles) and 3 facets: f‑vector (4, 6, 3), χ = 1 — a
triangulated disk, the "barycenter triangle" of the picture. `K × K` has 3 × 3 triangle pairs × C(4,2) = 6
staircase paths = **54 facets**, and `build("bary")` is the definition (`--complex bary`).

**Why the answer is 0, not 2.** The barycenter `3` lies in *every* facet, so `K` is the cone on ∂Δ² and ‖K‖ is
contractible — precisely the case the paper singles out just before defining `SC_strict`: *"A motion planner
defined on the full complex `K × K` exists only in the (topologically trivial) case that ‖K‖ is contractible."*
Here it exists explicitly. The constant map `c₃` is simplicial on every facet (its image is the single vertex `3`,
which every facet contains), and on a staircase facet of `σ × τ`

* `π₁ ∼ c₃`: the union of images is `σ ∪ {3} = σ`, a simplex — because `3 ∈ σ`;
* `c₃ ∼ π₂`: `{3} ∪ τ = τ`, likewise,

so `π₁ ∼ c₃ ∼ π₂` is a valid chain on **all 54 facets**: one domain, 3 maps, 2 links, `SC_strict = 0`. (No
smaller chain is possible: `π₁ ∼ π₂` fails on any facet with `σ ≠ τ`, e.g. `{0,1,3} × {1,2,3}`, where `σ ∪ τ`
has 4 vertices.) This is also the floor: `SC_strict ≥ 0` always. `independent_check.py` now rebuilds this complex
too (54 facets ⇒ three triangles, all six edges of `K₄`, χ = 1, one vertex in every facet) and its domain‑count
floor is 1 — the only certificate in the project where a single domain is the *sharp* answer.

## 25. How to interpret and use the planners (reading a certificate)

Every certificate in `results/` stores, per domain, a **chain of maps** `φ₀, …, φ_c : J → K`. That chain is not a
path — it is a whole *family* of paths, one per query, packed into `c + 1` tables. The paper's rationale for the
definition of a piecewise linear motion planner (intro, right after Definition 2.3) is exactly the reading:

> "for any given pair `(a,b)` of initial-final points in ‖J‖, the sequence of points
> `φ₀(a,b), φ₁(a,b), …, φ_c(a,b)` flags a piecewise linear path in ‖K‖ from `a` to `b` depending continuously
> on `(a,b)`."

So the motion plan for one query is obtained by **evaluating every map of the chain at that query and joining the
resulting points by straight segments**:

```
plan(a, b)  =  [ φ₀(a,b), φ₁(a,b), …, φ_c(a,b) ]        a polyline in ‖K‖
```

`φ₀ = π₁` is the start `a`, `φ_c = π₂` is the goal `b`, and the `c` interior waypoints are the "how". For
continuous query points `x ∈ σ`, `y ∈ τ` (not just vertices) each `φᵢ` is simplicial, hence affine on every
product facet: with `x = Σ λ_a a` and `y = Σ μ_b b`, the waypoint is `φᵢ(x,y) = Σ_{a,b} λ_a μ_b φᵢ(a,b)`. One
table entry per grid vertex, therefore, gives the plan for *every* point of the facet by interpolation.

**Why contiguity is the right hypothesis.** `φᵢ` and `φᵢ₊₁` 1‑contiguous on a facet `σ` means `φᵢ(σ) ∪ φᵢ₊₁(σ)`
is a simplex of `K`, so the straight segment from `φᵢ(v)` to `φᵢ₊₁(v)` stays inside `‖K‖` for every `v ∈ σ`. The
chain is thus a homotopy `H : ‖J‖ × [0, c] → ‖K‖` from `π₁` to `π₂`, and `plan(a,b)` is its track
`t ↦ H((a,b), t)`. Since every `φᵢ` is affine on each facet, `(a,b) ↦ plan(a,b)` is continuous (piecewise
linear): nearby start/goal pairs give nearby plans — the robustness the paper sells, and the reason the *number of
domains* is what `SC_strict` counts. `independent_check.py` verifies start `π₁`, end `π₂`, simpliciality and
1‑contiguity on **every** facet, i.e. precisely the hypotheses of this lemma — so a passing certificate proves
that *every* query in the domain has a valid plan, not merely the sampled ones.

**Reading one off a certificate.** Locate the query pair in the domain that contains it (the printed domains are
disjoint and cover `K × K`, so it is unique unless the pair sits on a shared face, where several domains apply —
either plan is valid, but *which* one you get cannot be chosen continuously; that discontinuity is the invariant
being measured). Entries marked `@` are grid vertices outside that domain: undefined for that planner, and no
other domain's table may be substituted there without breaking contiguity. Then:

```python
import independent_check as ic                     # the auditor doubles as parser (stdlib only)
name, KF = ic.detect_k("results/circle_probe3")
nv = max(max(f) for f in KF) + 1
domains, _ = ic.parse_cover("results/circle_probe3/cover.txt")
chains = ic.parse_planners("results/circle_probe3/planners.txt", domains, nv)
plan = [m[(0, 1)] for m in chains[1]]              # query (start 0, goal 1) on domain 1
# -> [0, 0, 2, 1, 1, 1]
```

Worked examples, all taken from audited certificates:

| certificate | query | domain 0 | domain 1 | reading |
|---|---|---|---|---|
| `bary_k1_c3` (1 domain, 54 facets, 2 links) | (0,1) | `0 → 3 → 1` | — | corner 0 → barycenter → corner 1 |
| `bary_k1_c3` | (1,1) | `1 → 1 → 1` | — | start = goal ⇒ stay put (found `m` keeps the diagonal) |
| `circle_probe3` (2 × 9 facets, 4/5 links) | (0,1) | `0 → 0 → 1 → 1 → 1` | `0 → 0 → 2 → 1 → 1 → 1` | one way round, or the other |
| `circle_probe3` | (1,0) | `1 → 2 → 2 → 2 → 0` | `1 → 1 → 1 → 1 → 0` | likewise, complementary |

The circle rows are the invariant in action: the same query receives plans going **the two different ways
around** `S¹` depending on the domain, and no single continuous rule can choose between them — that is why `S¹`
needs 2 domains (`TC + 1`) and why one domain exists only for contractible `‖K‖` (§24).

**Using the numbers.** Number of domains = `SC_strict + 1`, the only quantity `SC_strict` optimizes. Chain length
`c` = number of straight moves in the executed plan (a secondary cost, what the chain‑first energy minimizes:
wedge 2/5/5 links, circle 4/5, bary 2). Repeated waypoints (`0 → 0 → …`) are degenerate zero‑length segments and
are simply dropped when executing; whether a chain can be shortened further is the question of whether
non‑adjacent maps are contiguous, which for the wedge was settled exactly by a shortest path in the contiguity
DAG (§23). Domain sizes measure the slack of the cover (bigger domains = more queries per planner). Finally, a
plan is a path in the state space `‖K‖` (configuration space for a robot); turning it into joint‑space motion is
the application's own kinematics, and smoothing the polyline is allowed as long as it stays inside `‖K‖`.

**Two different senses of "short", which are easy to confuse when reading a certificate.** A chain can be *minimal as a
sequence of maps* — no sub-chain from `π₁` to `π₂` is contiguous on the domain, which is exactly what a shortest path in the
contiguity DAG decides (§23) — and every certificate in this report is minimal in that sense (cube guided 6/6/5 maps, S³
8/9/6, S³ `cmax 80` 10/8/3, wedge and barycenter likewise: the DAG saves 0 maps on all of them). That is *not* the same as
every individual query getting a shortest path. Measured pointwise on the cube certificate, **29 of the 64 vertex pairs**
receive a plan longer than the geodesic in the 1‑skeleton of `K` (42 of 64 for the product certificate) — the extreme case
being `plan(0,0) = 0 → 4 → 4 → 0 → 0`, a loop that returns to its start when `a = b`. This is forced by the formalism, not
by a weak search: each map is a *global* simplicial map on the domain and the contiguity condition must hold on **every**
facet at once, so the waypoints cannot be optimized for one query without breaking others. A useful sanity check when a plan
looks wrong is therefore the opposite one — *is a detour even allowed to be avoided?* On the cube, vertices `1` and `7` are
not adjacent (no edge or triangle contains both; neighbours of `1` are `{0,2,5,6}`, of `7` are `{0,2,3,4,6}`), so **every**
valid plan between them must pass through a third vertex: `plan(1,7) = 1 → 6 → 7` is not a defect but the geodesic, and a
two‑point `[1, 7]` plan is impossible for any correct certificate on this triangulation.

## 26. The cube boundary: a second triangulation of S², and where the search beats the products by five domains

Take the cube and triangulate its boundary: vertices `0..7` (bottom face `0,1,2,3`, top face
`4,5,6,7` directly above), the six square faces `{0,3,7,4}`, `{1,2,6,5}`, `{0,1,5,4}`, `{2,3,7,6}`,
`{4,5,6,7}`, `{0,1,2,3}`, each cut along its drawn diagonal (`0–7`, `1–6`, `0–5`, `2–7`, `4–6`,
`0–2`) into two triangles — **12 triangles**, `build("cube")`, `--complex cube`.

**The mesh is a sphere, and that is a computation.** 8 vertices; 18 edges (12 × 3 / 2, every edge in
exactly **two** triangles — there is no boundary); f-vector (8, 18, 12), χ = 2; and every vertex link
is a single cycle (link sizes 6, 4, 5, 3, 4, 4, 5, 5). A closed surface with χ = 2 is connected and
orientable, hence `‖K‖ ≅ S²` — the *same space* as ∂Δ³, in a different, non-minimal triangulation.
`independent_check.py` re-proves all of that from the facet list alone (every edge in exactly two
triangles, every link a cycle, χ = 2) before it audits any certificate.

`K × K` has 12 × 12 triangle pairs × C(4,2) = 6 staircase paths = **864 facets**, on an 8 × 8 = 64
vertex grid — the largest instance in this project whose whole certificate is still hand-checkable.

**The floor is the sphere's, but the products cannot reach it.** `SC_strict ≥ TC(S²) = 2`, i.e. at
least 3 domains, sharp at 2 — and ∂Δ³ *attains* the sharp value with three stars
(`results/s2_starcover`). Here a product domain is a rectangle `star(v) × star(w)` covering one
staircase facet of every pair `(σ, τ)` with `v ∈ σ`, `w ∈ τ`; the stars of this complex hold
6, 4, 5, 3, 4, 4, 5, 5 triangles, so the largest rectangle is `star(0) × star(0)`, i.e. 6 × 6 = 36 of
the 144 facet pairs = at most **216 facets**. Three domains would have to average 864/3 = 288 > 216:
**no 3-domain cover can be made of rectangles**. The exact branch-and-bound of `rect_cover.py` (≈2 s)
gives the rectangle-cover number

    rho(cube) = 8      (the counting bound alone only forces rho >= 5: 36+30+30+30 = 126 < 144)

with optimum `(v,w) = (0,0), (0,6), (7,2), (2,7), (6,6), (2,5), (6,0), (5,2)`, written up as the
companion certificate **`results/cube_starcover`**: 8 domains
216+180+108+108+102+78+48+24 = 864 facets, chains of 2/4/2/4/3/3/4/4 links, `SC_strict(cube) ≤ 7`,
audited (`independent_check.py`, exit 0).

That gap is worth tabulating against every other complex in this report — the exact rectangle-cover
number ρ against the fewest domains the theory allows (`TC + 1`):

| complex | ρ (products) | TC + 1 | products certify | theory allows |
|---|---|---|---|---|
| barycenter triangle (§24) | 1 | 1 | SC ≤ 0 = sharp | 0 (contractible) |
| ∂Δ³ (S²) | 3 | 3 | SC ≤ 2 = sharp | 2 |
| circle ∂Δ² (§14.3) | 3 | 2 | SC ≤ 2 | 1 (sharp) |
| wedge of two circles (§23) | 4 | 3 | SC ≤ 3 | 2 (sharp) |
| **cube boundary (§26)** | **8** | **3** | **SC ≤ 7** | **2** |

Everywhere else the product family is at most one domain from optimal; on the cube it is five away —
the wedge's phenomenon (§23: the search beats every product cover) at a much larger scale, and for a
*sphere*, where products had been optimal.

**The search closes it.** Four k = 3 attempts, all with the corrected energy (β 5, γ 0.5, track
moves) and `--complex cube --cmax 16`, the last two with the adaptive coverage guide:

|---|---|---|---|---|

| `results/cube_k3_v2` | the cold run above | — | 814 s, 60 epochs, 1.23 × 10⁹ moves | 820/864, sizes [382, 293, 391] — 44 short |

The two guided runs are the informative pair: cold, the guide drives coverage from 197 facets at epoch
1 to 858 at epoch 60 and then *stalls* — the whole population sits at 856–858, six facets unreachable
— whereas the same guide applied to the 820/864 state covers all 864 facets in 22 epochs. Warm
starting alone is not enough either (820/864 after three times the budget). What works is the pair:
a state that has already organised the three domains *and* the uncovered-facet weight increment to
close the remainder. The price of the sharp certificate is therefore 304 s *given* a good seed, and
the seed is the expensive part — which is worth remembering when reading the run time as a measure of
difficulty.

The winning run's reduction (Algorithm 2) produced the certificate `results/cube_k3_guided`:
**3 domains of 482 + 236 + 146 facets, chains of 5/5/4 links** (the raw pre-reduction domains,
482 + 384 + 348 = 1214, overlap; the certificate's are disjoint and cover exactly 864). Audited end
to end —

    VERIFIED: SC_strict(cube boundary (8 vertices, 12 triangles)) <= 2 by 3 explicit planner domains (subdivision level 0)

With the floor `SC_strict ≥ TC(S²) = 2`, this is **`SC_strict(cube) = 2` exactly**, at subdivision
level 0, on a triangulation where *no* product cover comes within five domains of it (ρ = 8). The
sphere ladder (§19, §22) and the wedge (§23) already showed the search beating the star cover; the
cube shows the gap can be large while the search still lands on the theoretical optimum.

The three chains are genuine homotopies, not collapse-to-a-point chains: their images (as maps on the
64-vertex grid) shrink to 4–5 of the cube's 8 vertices in the middle and return to 8, and *none* of
the 17 maps is constant — image sizes 8→6→4→4→7→8, 8→5→5→5→5→8, 7→6→4→6→8, with only 3–4 of the 64
grid vertices fixed through a whole chain. Compare §24, where the contractible case *does* have a
(constant) collapsing option and the annealer chose the non-constant one anyway.

Finally the sharp value is a level-0 statement: `SC_strict⁰ ≥ SC_strict¹ ≥ … = TC` means the
certificate proves 2 while the *floor* 2 is a property of the space, and the two agree — so for this
complex subdivision buys nothing, exactly as for ∂Δ³.

**A 2-domain control.** On S² the theory forbids a 2-domain cover (`TC(S²) = 2`), so `--k 2` is a
falsification test for the whole pipeline: if the auditor ever verified a 2-domain cover of the cube,
the energy or the checker would be wrong. `./run_cube.sh k2` [PENDING: result].

## 27. Exact rectangle-cover numbers: the hemi-polyhedra and the non-orientable surfaces

Corollary 2 turns the search for a motion-planner system into a **set cover with no
search at all**: every vertex pair `(v, w)` gives the product domain `D(v,w) = star(v) × star(w)`,
and the minimum number `ρ(K)` of such rectangles covering all `|F|²` facet pairs certifies
`SC_strict(K) ≤ ρ(K) − 1`. `ρ` depends only on the base complex — no GPU, no annealing, and the
certificate chains are the three-map chains `π₁ ~ c_v ~ … ~ c_w ~ π₂` of Theorem 1. It is a
set-cover instance with `|V|²` sets over `|F|²` elements, so every complex here is solved
**exactly** in seconds: `rect_cover.py` (bitmask branch and bound) and an independent
`scipy.optimize.milp`/HiGHS formulation agree wherever both finish (the branch and bound only
stops early where the search tree grows, as on the hemi-dodecahedron).

This settles the product bound for the whole non-orientable campaign (all hemi-polyhedra are
RP²; `build()` names in `gpu_sc.py`). The certificates are `results/<name>_starcover_opt`
(`_greedy` where greedy; all verified by the Definition 2.3 check of `star_cover.py` and written
in `independent_check.py` format):

| complex (`--complex`) | V: abstract → complex | Δ (complex) | `\|K×K\|` | ρ (exact) | star cover (domains → SC) | annealer / searched cover (domains → SC) |
|---|---|---|---|---|---|---|
| Möbius band (`mobius`) | 5 → 5 | 5 | 150 | **4** | `mobius_starcover_opt` (4 → ≤ 3) | CP-SAT `mobius_k3_sat` (3 → **= 2**, exact); annealer `mobius_k4_from_k5` (4 → ≤ 3) |
| hemi-icosahedron (`rp2`) | 6 → 6 | 10 | 600 | **6** | `rp2_starcover_opt` (6 → ≤ 5) | annealer `rp2_k6` (6 → ≤ 5) |
| hemicube (`hemicube`) | 4 → 7 | 12 | 864 | **7** | `hemicube_starcover_opt` (7 → ≤ 6) | annealer `hemicube_k7` (7 → ≤ 6; `hemicube_k6` incomplete) |

The `V: abstract → complex` column separates the abstract polyhedron/regular map from the
simplicial complex the code actually feeds to the annealer. `K` must be simplicial, so a
non-simplicial abstract polyhedron is subdivided *minimally*: the hemi-dodecahedron's six
pentagons are fanned into triangles from a vertex (10 → 10, no new vertex), the hemicube's
three squares are coned from a fresh centre (4 → 7, one per square), and the hemi-octahedron's
six edge cells — doubled, so no 3-vertex simplicial model exists — are split at a midpoint each

Klein bottle (8) and Császár torus (7) are simplicial triangulations already: abstract and
complex vertex counts coincide, with the complex the minimal triangulation of its space.

Two readings. First, the four hemi-polyhedra are four triangulations of the same space, RP², and
the star cover is a search-free certificate on each: `ρ = 6, 7, 9, 15` give `SC_strict(RP²) ≤ 5, 6,
8, 14` on the hemi-icosahedron, hemicube, hemi-octahedron and hemi-dodecahedron. On the first two
the annealer ties the product bound; on the hemi-octahedron the star-seeded `k = 8` run

attaining domains are provably non-product; on the hemi-dodecahedron the search has not reached
the product bound. The gap between `ρ − 1` and the searched value, wherever one exists, measures
how far the optimal domains are from being products. Second, the
**Möbius band was the first non-orientable surface where the search provably beats every product
cover**: `ρ = 4` certifies ≤ 3, but the CP-SAT three-domain cover (65+43+42) gives `SC_strict = 2`,
one domain below the entire product family (the hemi-octahedron above, the wedge §23 and the cube
§26 are the other search-beats-products cases). The product bound is an upper bound, never an
optimality claim.

**S² control: the dodecahedron (density ladder).** The `dodeca` complex — the 20-vertex,
36-triangle control of `experiments/dodeca_anneal_log.md`, 7776 product facets — has exact
`ρ = 36`, the largest value here. The minimum facet-transversal is `S = {0, 2, 8, 10, 12, 19}`
(τ = 6) and the 6×6 grid cover `S × S` attains 36 (`results/dodeca_starcover_opt`, 36 domains

`SC_strict(dodecahedron) ≤ 35` with no search; it is far from the `k = 3` campaign target, but the
structural point is that with `ρ(∂Δ³) = 3`, `ρ(cube) = 8` and `ρ(dodeca) = 36` three triangulations
of S² carry three different values: ρ is a combinatorial invariant of the triangulation, not a
homotopy invariant of the surface. The icosahedron rung (`icosa`, 12 vertices, 20 triangles, 2400
product facets — now in `build()`, the double cover of `rp2`) completes the ladder with exact
`ρ = 24`, row–transversal tight this time: `τ = 6` (`{0,2,4,6,8,10}`), `d = 5`, `F = 20`,
`⌈6·20/5⌉ = 24` (Lemma 6), matched by the 24-rectangle cover of `results/icosa_starcover_opt`
(150×3 + 126×5 + 102×6 + 78×7 + 54×3, chains 2–5 links, verified) ⇒ `SC_strict(icosa) ≤ 23`;
the covering LP is far weaker here (16.00), and the grid cover on a minimum transversal needs
36.  HiGHS's own certificate gap (incumbent 24, dual 23) is closed by Lemma 6, so 24 is exact.

**Using a star cover as a warm start.** `star_cover.py` now records the full-grid chains in
`summary.json` under `best_chains`, the key `gpu_sc.py` / `annealer_stretch.py --init` expects, so a
star certificate can seed the annealer at fewer chains (`k = ρ − 1`) and let it try to absorb the
dropped domain. For the hemi-octahedron the 9-domain star cover seeds 1440/1536 facets at `k = 8`
(the 96-facet domain is dropped); the run answers the direct test of whether `SC_strict ≤ 7` in a

motion planners`, sizes 258/237/224/186/175/160/150/146, chains 4/5/2/4/5/3/4/5 links), i.e.
**`SC_strict(RP²) ≤ 7`** one domain below the product floor, certificate `results/hemi_octa_k8`.
`hybrid_cover.py` is the complementary probe: keep the `m` largest star

## 28. Why ρ = V on the hemi-polyhedra (row–transversal, diagonal, grid)

§27 records the coincidence: on the hemi-icosahedron, the hemicube and the hemi-octahedron the
exact star-cover number equals the vertex count (`ρ = 6, 7, 9 = V`), so `SC_strict ≤ V − 1 =
5, 6, 8` with no search. The mechanism is three elementary bounds on `ρ` — not one per vertex,
but a lower bound from facet-transversals matched by diagonal/grid covers, with the subdivisions
of §27 supplying the arithmetic that makes both sides land on `V`. (Formal versions of Lemma 6,
Lemma 7 and Proposition 8 are in the paper, §5, after Corollary 3 there.) Notation as in §19:
`τ` = minimum size of a set of vertices meeting every facet of `K`, `d = max_v |star(v)|`,
`F` = number of facets.

**Lemma 6 (row–transversal bound).** `ρ(K) ≥ ⌈τ·F / d⌉`.

*Proof.* Let `R` be a cover by `ρ` rectangles. Fix a facet `s` and set `W_s = {w : ∃v ∈ s with
(v,w) ∈ R}`. Every facet `t` meets `W_s` (the pair `(s,t)` lies over some `(v,w) ∈ R` with
`v ∈ s`, `w ∈ t`), so `W_s` is a facet-transversal and `|W_s| ≥ τ`. Summing over the `F` facets
counts each rectangle once per `s` containing its first coordinate:
`Σ_{(v,w)∈R} |star(v)| = Σ_s |W_s| ≥ τ·F`. Every summand is at most `d`, hence `d·ρ ≥ τ·F`. ∎

Tight on `circle` (`⌈2·3/2⌉ = 3 = ρ`), `s2` (`⌈2·4/3⌉ = 3 = ρ`), `mobius` (`⌈2·5/3⌉ = 4 = ρ`),
`rp2` (`⌈3·10/5⌉ = 6 = ρ`) and `icosa` (`⌈6·20/5⌉ = 24 = ρ`); on `klein` and `torus` it gives 10
against `ρ = 12` and 11.

**Lemma 7 (diagonal and grid covers).** (i) If every two facets of `K` meet, the `V` diagonal
rectangles `(v,v)` cover `K×K`, so `ρ(K) ≤ V`. (ii) If `S ⊆ V` meets every facet of `K`, the
`|S|²` rectangles `(v,w)` with `v, w ∈ S` cover `K×K`, so `ρ(K) ≤ |S|²`.

*Proof.* A facet pair `(s,t)` lies over `(v,w)` as soon as `v ∈ s` and `w ∈ t`: take `v ∈ s ∩ t`
in (i), and `v ∈ s ∩ S`, `w ∈ t ∩ S` in (ii). ∎

**Proposition 8 (ρ = V on the three hemi-polyhedra).** For the stored minimal triangulations of
§27, `ρ = V` exactly:

| complex | V | τ | d | F | `⌈τF/d⌉` | covering LP | `ρ` (exact) |
|---|---|---|---|---|---|---|---|
| hemi-icosahedron (`rp2`) | 6 | 3 | 5 | 10 | **6** | 4.00 | **6 = V** |
| hemicube | 7 | 3 | 6 | 12 | 6 | 4.00 | **7 = V** |
| hemi-octahedron (`hemi_octa`) | 9 | 3 | 6 | 16 | 8 | **9.00** | **9 = V** |
| (contrast) hemi-dodecahedron | 10 | 4 | 9 | 18 | 8 | 11.11 | 15 ≠ V |
| (contrast) dodecahedron (S²) | 20 | 6 | 8 | 36 | 27 | **36.00** | 36 ≠ V |
| (contrast) icosahedron (S²) | 12 | 6 | 5 | 20 | **24** | 16.00 | 24 ≠ V |
| (contrast) Möbius band | 5 | 2 | 3 | 5 | **4** | 2.78 | 4 ≠ V |
| (contrast) Klein bottle | 8 | 4 | 7 | 16 | 10 | 7.11 | 12 ≠ V |
| (contrast) Császár torus | 7 | 4 | 6 | 14 | 10 | 5.44 | 11 ≠ V |

*Hemi-icosahedron (`rp2`), hand proof both sides.* The ten facets pairwise meet — no two of the
ten triples on six vertices are disjoint (facet table of `build("rp2")`, 0 disjoint pairs) — so
Lemma 7(i) gives `ρ ≤ 6`. Lemma 6 gives `ρ ≥ ⌈3·10/5⌉ = 6` (`τ = 3`: two stars cover at most
`5+5−2 = 8 < 10` facets). The diagonal cover of `rp2_starcover_opt` attains it.

*Hemicube, hand proof both sides.* Each facet is a square centre together with an edge of `K₄` on
the four cube-vertices `0–3` (the 12 triangles are the 3 coned squares; as unordered pairs the
square edges run through the 6 edge types of `K₄`, each in 2 squares). Here `τ = 3` (the three
centres meet every facet), `d = 6`, `F = 12`, so Lemma 6 gives `ρ ≥ 6`. Suppose six rectangles
covered. In `Σ_{(v,w)∈R} |star(v)| ≥ 36` every summand would have to equal 6 — a single centre
first-coordinate caps the sum at `5·6 + 4 = 34 < 36` — and the same holds on the second
coordinate, so all six rectangles are cube-vertex pairs. Coverage of the 12 triangles then reduces
to coverage of the 36 ordered edge-type pairs of `K₄` (a triangle contains exactly the two
cube-endpoints of its edge type). For `R` of size 6 put `W_x = {w : (x,w) ∈ R}`. The pair
`(e,f)` is covered iff `(W_a ∪ W_b) ∩ f ≠ ∅` for `e = {a,b}`, so every union `W_e := W_a ∪ W_b`
must meet all 6 edges of `K₄`, i.e. `|W_e| ≥ 3`. But `Σ_e |W_e| ≤ Σ_x 3·|W_x| = 18`, with
equality only if the four `W_x` are pairwise disjoint (`K₄` is complete) and `Σ_x |W_x| = 6` —
impossible inside a 4-element ground set (pairwise disjoint sets sum to ≤ 4). Hence `ρ ≥ 7`;
`hemicube_starcover_opt` attains 7 with the pairs
`(0,0) (0,1) (1,2) (1,0) (3,1) (2,3) (3,2)` on the cube-vertices, and `rect_cover.py` plus the
HiGHS integer program certify the same optimum. And `7 = 4 + 3 = V_abs + F_abs = V`: the coned
triangulation adds exactly one centre per square.

*Hemi-octahedron, hand upper + certified lower.* Corners `0,1,2` (|star| = 4) and the six
edge-cell midpoints `3–8` (|star| = 6). Every one of the 16 facets meets `S = {0, 5, 6}` — the
corner `X` and the two midpoints `C, D` of the `Y–Z` edge cell — so Lemma 7(ii) gives `ρ ≤ 9`.
The same count is forced on the vertex side: the medial subdivision adds one vertex per edge
cell and the doubled complete abstract 1-skeleton has `2·C(3,2) = 6` edge cells, so
`V = 3 + 6 = 3² = |S|²`. For the lower bound Lemma 6 only reaches 8 (`τ = 3`, `F = 16`, `d = 6`),
but the set-cover LP is **tight** here — value `9.0`, dual certificate from HiGHS, the only
complex computed with zero integrality gap (contrast `rp2` 4.00 and `hemicube` 4.00 below their
integer optima) — and `rect_cover.py` / the HiGHS integer program certify `ρ = 9` optimal
(`hemi_octa_starcover_opt` attains it with the grid `S²`). Hence `ρ = 9 = V`. ∎

**Consequence.** `SC_strict ≤ V − 1`: **≤ 5** (hemi-icosahedron), **≤ 6** (hemicube),
**≤ 8** (hemi-octahedron) — Corollary 2 applied to Proposition 8, zero search. The star-seeded
`k = 8` annealer run on the hemi-octahedron subsequently beat the product floor by one domain
(`SC_strict ≤ 7` with 8 < ρ = 9 rectangles, so the attaining domains are provably non-product —
`results/hemi_octa_k8`, §27), as the Möbius band, the wedge (§23) and the cube (§26) do on their
surfaces.

**Why the coincidence is not a law of RP².** `ρ` is an invariant of the star-incidence of the
chosen triangulation, not of the underlying surface: on the hemi-dodecahedron (same RP²) it is
15 = `E_abs` ≠ 10 = V; on the Möbius band 4 < 5 = V (Lemma 6 is tight there, the diagonal merely
non-optimal); on the Klein bottle and Császár torus 12 and 11 exceed 8 and 7. The three
coincidences are the three ways the minimal subdivision of a hemi-polyhedron can pay exactly the
gap: no subdivision and no disjoint facet pairs (hemi-icosa), one centre per face with the
`K₄` edge-pair optimum landing on `V_abs + F_abs` (hemicube), one midpoint per edge cell with
`V_abs + 2·C(V_abs,2) = V_abs²` (hemi-octa).
